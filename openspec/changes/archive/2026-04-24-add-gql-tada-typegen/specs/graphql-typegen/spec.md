## ADDED Requirements

### Requirement: Schema file exported from API
The API SHALL write the GraphQL schema to `schema.graphql` at the repo root on application bootstrap. The file SHALL be committed to version control and kept up to date whenever API types change.

#### Scenario: Schema file present after API starts
- **WHEN** the NestJS application bootstraps
- **THEN** a `schema.graphql` file exists at the repository root containing the full GraphQL schema in SDL format

#### Scenario: Schema file reflects current API types
- **WHEN** a GraphQL type, field, or enum is added or changed in the API
- **THEN** restarting the API updates `schema.graphql` to reflect the change

---

### Requirement: gql.tada introspection file committed
The web app SHALL include a committed `introspect.d.ts` file generated by `gql.tada` from `schema.graphql`. This file SHALL be regenerated whenever `schema.graphql` changes.

#### Scenario: Fresh clone typechecks without extra steps
- **WHEN** a developer clones the repository and runs `yarn typecheck` in `apps/web`
- **THEN** TypeScript resolves all gql.tada types without requiring a code generation step

#### Scenario: Introspection file regenerated after schema change
- **WHEN** `schema.graphql` changes
- **THEN** the developer runs the schema update script and commits the updated `introspect.d.ts`

---

### Requirement: GraphQL query documents are typed via gql.tada
All GraphQL query, mutation, and subscription documents in `apps/web/graphql/*.ts` SHALL be defined using the `graphql()` function from `gql.tada` instead of raw string literals.

#### Scenario: Query document infers result type
- **WHEN** a `graphql()` call selects a subset of fields from a type
- **THEN** TypeScript infers a result type containing only the selected fields — not the full schema type

#### Scenario: Query document infers variable type
- **WHEN** a `graphql()` call declares query variables (e.g. `$campaignId: ID!`)
- **THEN** TypeScript enforces the correct variable shape when the document is passed to `useQuery`

#### Scenario: Misspelled field name is a compile-time error
- **WHEN** a `graphql()` call references a field name that does not exist on the queried type
- **THEN** TypeScript reports a type error — no runtime request is required to surface the mistake

---

### Requirement: Hand-written interface duplication removed
TypeScript interfaces in page and component files that duplicate GraphQL response shapes SHALL be removed. Types SHALL be derived from `gql.tada` inference instead.

#### Scenario: useQuery data is typed without manual type parameter
- **WHEN** `useQuery` is called with a typed document node produced by `graphql()`
- **THEN** `data.value` is typed to match the query's selection set with no explicit generic argument

#### Scenario: Removed interface does not break typecheck
- **WHEN** a hand-written interface (e.g. `NpcRosterItem`, `DiaryEntry`) is deleted
- **THEN** `yarn typecheck` in `apps/web` passes without errors

---

### Requirement: JSON custom scalar mapped to unknown
Fields typed as the `JSON` custom scalar in the GraphQL schema SHALL be typed as `unknown` in the frontend. Components that consume these fields SHALL cast them to their expected shape locally.

#### Scenario: JSON scalar field is accessible as unknown
- **WHEN** a query selects a field with scalar type `JSON` (e.g. `abilityScores`, `spellSlots`)
- **THEN** the inferred TypeScript type for that field is `unknown`

#### Scenario: Component casts JSON field to expected shape
- **WHEN** a component needs to render a JSON scalar field
- **THEN** the component casts the `unknown` value to its expected type (e.g. `as Record<string, number>`) and handles nullability explicitly
